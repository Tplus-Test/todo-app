# タスク解決レポート：アーキテクチャ戦略および方針決定

## [CIT-1] AI/LLM サイテーション対策戦略 (#16)

### 1. 目的
自社サイトを持たない店舗向けに、ポータルサイトを通じたサイテーション獲得の具体的な実行計画を策定し、AI Overviews（AIO）およびLLM検索結果での可視性を確保する。

### 2. 候補プラットフォームと比較マトリックス

#### 2.1 参考資料：他社プラットフォーム採用事例
本レポートの戦略策定にあたり、以下の競合他社データおよびプラットフォームのリストを参考にしました。
* **参照ファイル:** `citation.png`

| プラットフォーム | SEO/AIへの影響度 | 設定工数 | カテゴリ | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| **Googleビジネスプロフィール** | 高 | 1.0〜2.0h / 店舗 | コアローカルSEO | 必須。AIO/LLMの主要データソース。 |
| **Apple Maps** | 中〜高 | 0.5〜1.0h / 店舗 | コアローカルSEO | LLMからの高い信頼性。設定が迅速。 |
| **ホットペッパー** | 高（ニッチ） | 高（有料） | 業界特化ポータル | AIのデータ抽出に有効だが業界限定。 |
| **Facebookページ** | 中 | 1.0h / 店舗 | SNS | NAPデータに最適。ミニサイトとして機能。 |
| **Yahoo!ロコ** | 中 | 1.0h / 店舗 | 国内ポータル | 国内ローカル検索において関連性が高い。 |
| **エキテン** | 低〜中 | 1.5h / 店舗 | 国内ポータル | 一般的なNAP情報の統一性確保に有効。 |
| **Instagram / TikTok** | 低（AI視点） | 非常に高 | 視覚特化SNS | 構造化データの抽出には不向き。 |

### 3. 戦略的推奨案（決定事項）
**決定事項:** MVPフェーズでは**「Googleビジネスプロフィール」および「Apple Maps」**に完全フォーカスする。

**選定理由:** サイトがない店舗では構造化データの埋め込みができないため、手動プロファイル作成が必須。主要2プラットフォームでAIサイテーション効果の約80%をカバー可能。SNSは構造化データの抽出が困難なため、優先度を下げて運用する。

### 4. ポータルサイト掲載の具体的な手順
1.  **事前準備:** 全店舗の標準化されたNAP（名称・住所・電話）をスプレッドシートに集約。
2.  **アカウント準備:** 登録用の共有Google/Appleアカウントを準備。
3.  **データ入力:** 各プラットフォームの登録ページから情報を入力。
4.  **オーナー確認:** 店舗スタッフと連携し、ピンコード認証を完了。
5.  **最適化:** 写真と説明文を追加。

### 5. Acceptance Criteria (AC) 定義
* 標準化されたNAPデータのマスタースプレッドシートが作成されていること。
* Google/Appleのアカウント作成とオーナー確認が完了していること。
* 各プロファイルに地域最適化された説明文が追加されていること。

## [VM-1] ボイスメモツール選定方針 (#17)

### 1. 目的
外部ボイスメモツールを3つ以上調査・比較し、採用ツールと連携方法を決定する。

### 2. 候補ツールの評価マトリックス

| ツール / アプローチ | 機能 | 料金 | 制約 | 形式 |
| :--- | :--- | :--- | :--- | :--- |
| **Native MediaRecorder** | ブラウザ内蔵機能 | 無料 | 旧iOS(14.3未満)非対応 | .webm, .mp4 |
| **RecordRTC** | クロスブラウザ対応 | 無料 | 依存関係の追加 | .wav, .webm |
| **Vocarooウィジェット** | 外部ホスト型 | 無料 | カスタマイズ不可・リスク有 | リンクのみ |

### 3. アーキテクチャ上の推奨案（決定事項）
**決定事項:** ブラウザ標準の **Native MediaRecorder Web API** を採用する。

**選定理由:** 外部ライブラリを避けることで技術的負債を抑え、高パフォーマンスを維持。エンジニア側でUIの状態を完全にコントロールできるため。

### 4. 統合のブループリント
1.  カスタムReactコンポーネント `<VoiceRecorder />` を作成。
2.  `getUserMedia({ audio: true })` でマイク許可を取得。
3.  `new MediaRecorder(stream)` で音声キャプチャ。
4.  録音完了時に `Blob` にコンパイルし、サーバーへ POST 送信。

**データフロー:**
`[User Mic]` → `[MediaRecorder]` → `[Blob]` → `[Next.js API]` → `[STT API]` → `[Text]`
