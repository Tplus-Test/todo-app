# [CIT-1] サイテーション対策調査：NAP一括配信の仕組みと連携先ポータル (#62)

## 1. 調査目的
NAP（名前・住所・電話番号）情報を複数のポータルサイトやマップサービスへ一括配信するサービスの仕組み、および主要なサービスの比較調査。※本調査では、サイテーション対応サイトの具体的な範囲確定はスコープ外とする。

## 2. NAP一括配信の仕組み（メカニズム）
一括配信サービスは、主に「ハブ＆スポーク」モデル（中央管理・一括送信）で動作します。

- **API連携（直接同期）:** Googleビジネスプロフィール、Apple Maps、Facebookなどの主要プラットフォームのAPIを利用し、リアルタイムで情報を更新・同期します。
- **一括送信/クローリング:** APIが公開されていない国内ポータルサイトやディレクトリに対しては、独自の送信システムやクローラーを用いてデータを同期します。
- **データ正規化:** 表記の揺れ（「3-1-1」と「三丁目一番一号」など）を自動修正し、すべての媒体で同一のNAP情報を維持します。

## 3. 主要サービスの比較
| サービス名 | 配信メカニズム | 主な連携先ポータル | 特徴・強み |
| :--- | :--- | :--- | :--- |
| **Canly (カンリー)** | API + 独自連携 | Google, Apple, FB, 各種国内SNS | 国内店舗向け。サポートが充実しており、日本の小売チェーンでシェアが高い。 |
| **Gyro-n (ジャイロン)** | API + MEO解析 | Google, Apple, FB, 国内マップ等 | 日本国内のMEO（マップ検索最適化）分析や順位計測機能が非常に強力。 |
| **Yext (イエクスト)** | グローバルAPI | 200以上のグローバル検索エンジン | 世界標準。圧倒的な連携数を誇るが、エンタープライズ向けでコストは高め。 |
| **MEOダッシュ** | API + レポート | Google, Apple, 連携ポータル等 | 複数店舗のデータを一元管理し、運用成果をレポーティングすることに特化。 |

## 4. 考察
MVP開発において自社でどこまで実装するかを検討する際、国内シェアが高くAPI連携が安定している **Canly** や **Gyro-n** のハブ機能（一度の入力で複数APIへPOSTする仕組み）が優れたモデルケースとなります。




# [VM-1] ボイスメモツール調査・選定 (#17)

## 1. 調査目的
ブラウザAPI（Native MediaRecorder等）の調査ではなく、既存の「外部Webサービス/ツール」を比較し、機能やUI/UXのベストプラクティスを選定する。

## 2. 外部ツールの比較（4サービス）
| ツール名 | 主要機能 | UI/UXの傾向 | メリット / デメリット |
| :--- | :--- | :--- | :--- |
| **Online Voice Recorder** | 録音、トリミング | シンプルで無機質。 | 【◎】インストール不要で手軽<br>【×】広告が目立つ |
| **Rev Online Recorder** | 高音質録音、MP3保存 | 清潔感のあるモダンなデザイン。 | 【◎】UIが非常に分かりやすく直感的<br>【×】クラウド共有機能がない |
| **Vocaroo** | 即時リンク発行、共有 | クラシックなWeb 2.0スタイル。 | 【◎】録音後すぐにURLで共有可能<br>【×】デザインが古く、埋め込みにくい |
| **Sodaphonic** | オンライン波形編集 | 多機能な編集画面。 | 【◎】ブラウザ上で高度な切り貼りが可能<br>【×】シンプルさを求めるユーザーには複雑 |

## 3. 考察と推奨方針
plusoneプロジェクトにおけるボイスメモ機能のUI/UXとしては、以下の要素を組み合わせた形が理想的です。

1. **録音体験:** **Rev** のような「迷わない清潔なUI（ワンクリック録音）」
2. **共有体験:** **Vocaroo** のような「保存後に即座に共有リンクを発行できる利便性」

外部APIやウィジェットとして組み込めるツールがない場合でも、上記の2つのUXをモックアップ設計の基準とすることを推奨します。
