# [CIT-1] サイテーション対策調査：NAP一括配信の仕組みと連携先ポータル (#62)

## 1. 調査目的
NAP（名前・住所・電話番号）情報を複数のポータルサイトやマップサービスへ一括配信するサービスの仕組み、および主要なサービスの比較調査。

※本調査では、サイテーション対応サイトの具体的な範囲確定はスコープ外とする。

---

## 2. NAP一括配信の仕組み（メカニズム）
一括配信サービスは、主に「ハブ＆スポーク」モデル（中央管理・一括送信）で動作します。

- **API連携（直接同期）:** Googleビジネスプロフィール、Apple Maps、Facebookなどの主要プラットフォームのAPIを利用し、リアルタイムで情報を更新・同期します。
- **データ正規化:** 表記の揺れ（「3-1-1」と「三丁目一番一号」など）を自動修正し、すべての媒体で同一のNAP情報を維持します。

### 2.1 API未対応媒体への独自配信ロジック（深掘り調査）
APIが公開されていない国内ポータルサイトに対しては、一括配信ツール側が以下の手法を用いて擬似的な自動化・同期を行っています。

* **対象となる具体的な国内媒体（例）:**

| カテゴリ | 媒体名 |
| :--- | :--- |
| **飲食系** | 食べログ、ぐるなび、ホットペッパーグルメ |
| **総合・地域ディレクトリ** | エキテン、Yahoo!ロコ |
| **国内マップ** | goo地図、Mapion |

* **主な連携・同期手法:**
  1. **RPA / スクレイピング技術（ブラウザ自動化）:** PuppeteerやSeleniumなどの技術を用い、配信ツール側のサーバーが対象ポータルの管理画面に自動ログインし、フォームへの入力や更新ボタンのクリックをシステム的に代行（クローリング更新）します。
  2. **CSV一括アップロードの自動化:** 対象媒体がCSVでの一括更新機能を持っている場合、システム側で規定のフォーマットにデータを変換し、定期的に自動アップロード処理を行います。
  3. **手動更新代行（ハイブリッド型）:** システム化が困難な一部のレガシーサイトに対しては、配信サービス側のオペレーターが管理画面から手動で更新を代行するケースも存在します。

---

## 3. 主要サービスの比較
| サービス名 | 配信メカニズム | 主な連携先ポータル | 特徴・強み |
| :--- | :--- | :--- | :--- |
| **Canly (カンリー)** | API + 独自連携 | Google, Apple, FB, 各種国内SNS | 国内店舗向け。サポートが充実しており、日本の小売チェーンでシェアが高い。 |
| **Gyro-n (ジャイロン)** | API + MEO解析 | Google, Apple, FB, 国内マップ等 | 日本国内のMEO（マップ検索最適化）分析や順位計測機能が非常に強力。 |
| **Yext (イエクスト)** | グローバルAPI | 200以上のグローバル検索エンジン | 世界標準。圧倒的な連携数を誇るが、エンタープライズ向けでコストは高め。 |
| **MEOダッシュ** | API + レポート | Google, Apple, 連携ポータル等 | 複数店舗のデータを一元管理し、運用成果をレポーティングすることに特化。 |

---

## 4. 考察（アーキテクチャ視点）
本調査の目的は特定サービスの選定ではなく、NAP一括配信の仕組み理解にある。
その観点では、各サービスに共通して以下のアーキテクチャパターンが確認できた：

- 中央データベースによるNAP情報の一元管理（Single Source of Truth）
- 外部プラットフォームとのAPI連携によるデータ同期
- API未対応媒体への独自配信ロジック（RPA・CSV自動アップロード・手動連携等）
- データ正規化による表記揺れの統一

これらの構成は、MVP開発においてNAP配信機能を設計する際の重要な参考パターンとなる。

# [VM-1] ボイスメモツール調査・選定 (#17)

## 1. 調査目的
ブラウザAPI（Native MediaRecorder等）の調査ではなく、既存の「外部Webサービス/ツール」を比較し、機能やUI/UXのベストプラクティスを選定する。

---

| ツール名 | URL | 主要機能 | UI/UXの傾向 | メリット / デメリット |
| :--- | :--- | :--- | :--- | :--- |
| **Online Voice Recorder** | [https://online-voice-recorder.com/](https://online-voice-recorder.com/) | 録音、トリミング | シンプルで無機質。 | 【◎】インストール不要で手軽<br>【×】広告が目立つ |

---

## 3. 考察と推奨方針（Decision）
当初は自前実装を検討していましたが、開発コストと運用負荷の観点から、**既存の外部サービスの導入を推奨**します。

用途やプロジェクトの優先事項に応じた有力候補は以下の通りです。

* **候補 1：【共有のスピード重視】Vocaroo**
  * **URL:** [https://vocaroo.com/](https://vocaroo.com/)
  * **理由:** 音声を保存することなく、ワンクリックで共有URLが発行されるため、チーム内での素早いコミュニケーションや、チケットへのリンク貼り付けに最も適しています。UIは古いですが、業務効率は最大化されます。
* **候補 2：【音声の品質・信頼性重視】Rev Online Recorder**
  * **URL:** [https://www.rev.com/onlinevoicerecorder](https://www.rev.com/onlinevoicerecorder)
  * **理由:** クライアントへ送信する正式な音声など、ノイズが少なく高品質な録音が求められる場合に最適です。UIも洗練されており、リテラシーを問わず使いやすい点が強力です。（ただし、ファイルのアップロード・共有フローは別途必要になります）
* **候補 3：【編集機能重視】Sodaphonic**
  * **URL:** [https://sodaphonic.com/](https://sodaphonic.com/)
  * **理由:** 録音した音声の一部をカットしたい、繋ぎ合わせたいといった「編集要件」が発生する場合は、ブラウザ上で完結するこのツールが唯一の選択肢となります。

---

## 4. 最終推奨
「手軽なボイスメモの共有」という本来の目的を鑑みると、フローに摩擦を生まない **Vocaroo** の利用が第一候補として推奨されます。
